- Routing lives in registry/workflows.json (18 one-word workflows, one per worker), mirrored by src/lib/runtime/workflows.ts in the VISION app; .github/workflows/*.yml are generated by scripts/gen_workflows.py, never hand-edited. Why: dispatcher, relay pin and runner must agree on one table.
- Workers (workers/<name>/index.py) only scope-check and verify outputs through runtime/worker_base.py; conversion logic stays in runtime/operations.py + format_ops.py. Why: no duplicated generation logic.
- Story generation lives in workers/documents/story.py; only documents.yml passes repository secrets, and only when the operation is story_generate. Why: credentials never reach file workflows.
- Every workflow is workflow_dispatch only. Why: nothing runs unless VISION dispatches a job.
